# Rift Build Lab
Independent website and optional Windows desktop application for a League player exploring damage tradeoffs and unusual kit-based builds. Formula snapshot: 26.20 / 16.20.1. All 173 champions and AI-authored hypotheses are browsable. Partial numerical adapters cover selected objectives for all 173 champions, including the original Cassiopeia Q/E, Sett W, noncritical Blitzcrank E and Tahm Kench Q/W/enemy R models. Coverage does not establish full-kit or full-build simulation. Unresolved crit/proc mechanics remain explicitly unverified. Hypotheses are not validated gameplay recommendations. Runtime AI generation is not available in this release.

User instructed us to proceed with the app. Inferred preferences: local-first, no accounts or API key, repeatable calculations, explicit coverage, keyboard-accessible desktop tool with mobile support.

The user chose this existing ChatGPT conversation as the build authoring workflow. The app prepares a local request, and the assistant writes complete proposals into the workspace inbox when asked here. The app loads the proposals for calculation and manual game tests, retaining observations for the next revision. It cannot independently invoke or message this conversation. The first inbox contains three Cassiopeia and three Sett experiments.

The published GitHub Pages app refreshes OP.GG and Lolalytics references daily. Provider freshness, formula snapshots and authored hypotheses have separate provenance. Observed provider cores can be loaded or pinned as baselines, retaining role, patch and sample; relative modeled comparisons require equal item counts and both setups within shared constraints. Baseline cores are not expanded into invented full builds. Valid working drafts restore after refresh; recorded tests support repeated measurements, a manual baseline and explicit ability/form/sequence conditions.


**Meta & teams** provides a current-source six-item recommendation for every champion in its configured provider role. Individual late-slot observations and explicit kit completions remain distinct from observed cores; joint six-item performance is not inferred. Local composition rules use four allies, five enemies and confirmed threat flags to explain optional-item/defensive-boot swaps while retaining source cores and their completions. Team drafts persist per champion; test proposals carry composition and source notes into manual testing. Daily publication validates full-roster completion after refreshing providers.


Matchup requests rank compatible counter-item needs using damage/survival preference and an identified main threat before optional slots are assigned. Searchable team slots prevent duplicate champions; item locks preserve chosen purchases. Full original/adapted inventory comparison shows costs and listed stats without claiming passive-aware damage. Role/provider choice uses qualified source observations and reviewed completion pools; unavailable lanes stay explicit. New historical test records retain the complete immutable proposal snapshot, including teams and source context. Purchase checkpoints guide starts, recalls, core and situational timing; mobile exposes direct team setup and compact inventory.

Build transfers now accept native scenario JSON, companion items + runes bundles, and League item sets with block selection. Imports require a validated preview before replacing the workspace; unsupported or incompatible items are rejected. Item sets without runes explicitly load defaults. The selected rune page shows icons and expandable effect text, with editing controls retained. The test bench purchase planner uses exact subset dynamic programming to maximize completed-item damage integrated over gold spent for the selected fixed ability/target conditions. It excludes component stats and match utility, resets earned progression stacks, and normalizes earned item upgrades to their shop prerequisites. Applying an order updates equipped order and exported purchase blocks. Live League client application still requires local companion testing.


The optional desktop preview uses Tauri 2, a window-independent Rust core and system WebView2. Shared UI/data remain deployable to GitHub Pages. Native capabilities include local League discovery, verified transport, backups, item-set/rune-page application, opt-in champion-select monitoring and preferred build selection. No cloud account, gameplay automation, automatic purchases or bundled Python/Node/Chromium runtime is required. Tray-on-close and Windows startup are separate opt-ins. Background mode releases the webview; invalid or unsaved drafts keep the window open. Current verification and live-client limitations are recorded in `docs/desktop-verification.md`; do not equate fixture coverage with live League compatibility. This is an unofficial fan tool, not endorsed by Riot Games.

The open desktop window uses a native WebView2 memory target: after 15 seconds idle or on blur it requests lower cache/page residency; input/focus restores normal mode and active damage searches stay in normal mode. Scripts and page state remain alive. This reduces idle resident RAM, not an enforceable total-memory quota. The policy is absent from the independent website bundle; its build output remains unchanged by this desktop fix. See `docs/desktop-memory-optimization.md` for measurements and active-use limits.
